# 《请勿喧哗》网页重建：渐进式框架与分阶段实施方案 v4.0

**适用情况**：现有 Qt 游戏层难以稳定运行，需要保留 B 的 Python 识别、C 的 `story.json`、D 的分层美术和音乐设计，在两小时内获得一个可以继续打磨、而不是一次性演示的网页框架。

**重要界限**：这是新网页实现的开发方案，**不覆盖**原剧本、不删除 Qt 工程；第 0 阶段仅承诺稳定骨架和可演示关键闭环，不能把模拟输入伪称真实识别，也不能把有占位场景的骨架称为完整作品。

## 0. 技术栈及必须安装的软件

| 类别 | 使用内容 | 是否必须 | 说明 |
|---|---|---|---|
| 编辑器 | VS Code 或你熟悉的文本编辑器 | 是 | 编辑 Python、JS、CSS 和 JSON；不需要新增 IDE |
| 浏览器 | Chrome 或 Edge 最近稳定版本 | 是 | 本地运行、DevTools 调试、全屏路演 |
| 运行环境 | Python **B 现有手势程序已经验证可用的版本与虚拟环境** | 是 | 不贸然升级 MediaPipe、Python 和依赖；新 HTTP 服务仅用 Python 标准库 |
| 版本管理 | Git | 是 | 原 Qt 工程只读备份；新工程独立目录／独立分支，每阶段打稳定标签 |
| 前端 | 原生 HTML/CSS/JavaScript | 是 | 不用 React/Vue/Node/npm/打包器，减少两小时内的部署风险 |
| 本地桥接 | Python 标准库 `ThreadingHTTPServer` + `subprocess` | 接真实摄像头时 | 浏览器只请求本地服务，摄像头仅由 B 的 Python 进程打开 |
| 美术 | 已有病房图、深海图，后续导入 D 的透明 PNG | 是 | 先用现有素材；新图层可替换占位元素，不改游戏逻辑 |
| 音频 | 浏览器 `<audio>` / Web Audio API | 后续 | 先留音频事件钩子；实际 BGM 到位再接入 |
| 可选工具 | ffmpeg、GIMP/Krita、浏览器性能面板 | 非必须 | 剪备用视频、检查 PNG 透明边缘、帧率测试 |

**启动方法**：在新工程运行 `python server.py`，用浏览器打开本地地址（通常为 `http://127.0.0.1:8765`）。真实识别模式在确认 B 程序的准确脚本路径、工作目录、JSONL 格式后，通过启动参数添加；**不能假设 `gesture_demo.py` 在工程根目录**。

## 1. 结构：三层解耦，任何一层都可替换

```text
保留的 B Python 摄像头识别程序（唯一摄像头所有者）
    stdout：JSONL；stderr：调试日志
                 │
                 ▼
Python 本地桥 server.py
    启动/退出子进程、读取真实事件、环形事件队列、状态新鲜度
                 │ HTTP localhost（最新状态 + since_id 事件增量）
                 ▼
浏览器：InputAdapter → GameController → SceneRenderer
                         │                 │
                plotRules.js            scenes + effects
                 │                 │
      原 story.json ID + 文案       原 PNG / D 的新 PNG / 音乐
```

- **输入层 InputAdapter**：接收 B 的事实性输出，标准化 `PALM/GOOD/WAVE/SILENCE_STATE/SILENCE_REACHED/NO_HAND/CUP(待交付)`。开发键盘模拟输入走同一个入口，但界面必须醒目标识“模拟输入”。一次性 `WAVE` 等事件带队列 ID；连续静止状态以最新时间戳为准。不要凭空使用尚未确认的面部识别。
- **逻辑层 GameController**：单一可信场景状态机；控制每次对白是否出现、能否跳场景、何时播放转场及音乐。B 不能直接切换页面，D 的动画不能判定是否通关。
- **表现层 SceneRenderer**：每个场景可用一张图片＋字幕占位，再逐渐升级为层次丰富的动画。以游戏公开状态更新，比如 `waterIntensity`、`fishProximity`、`specialFishProximity`、`glassOpacity`、`captionId`；不要在每个场景重复写一份识别逻辑。
- **数据层**：原 `story.json` **原样复制**；额外的 `plotRules.js` 负责把对白 ID 映射到可执行条件。C 修改台词时不让 AI 理解中文 `trigger` 并自行生成新规则。
- **音频层**：事件驱动（进入病房、GOOD 成功、初次聚鱼、妹妹先伸手、最后 PALM），和剧情 ID 解耦。静音下必须能完成全部剧情。

### 固定兼容规则

目前已知 B 的消息是：`{"type":"PALM","x":0.43,"y":0.58}`；`{"v":1,"type":"WAVE","ts_ms":...}`；`{"type":"SILENCE_STATE","state":"STILL|MOVING|NO_HAND","still_ms":...,"motion":...}`；`{"type":"SILENCE_REACHED"}`；还存在 `GOOD`。实际字段以 **B 最终真实 stdout** 为准；`CUP` 尚非已交付功能。

对原输出仅做**适配**，不要要求 B 为网页重写一套模型。JSONL 中一行无效数据跳过并记日志，不使游戏崩溃；保留最近事件 ID，前端按序消费，不能只取最新消息（会漏掉 WAVE）。连续状态如果过期约 1 秒，则按识别失联处理，**不能判定为静止**。摄像头脱离／`NO_HAND` 时也必须中断静止。

输入优先级：**暂停/帮助菜单 > 当前场景可用手势 > 静止背景状态**。关菜单后清空动作缓存，并等待约 300ms，防止误触剧情。跨场景丢弃旧离散事件；终局静止必须在终局真正进入等待阶段之后单独累计满约 2 秒，不能复用深海的 `SILENCE_REACHED` 或上个场景留下的 `still_ms`。

## 2. 全剧情节点实施清单：按照用户现有 `story.json` 的 sceneOrder

| 场景与必须保持的剧情 | 第 0 阶段可运行占位版 | 可渐进打磨的正式版 | 进入下一场景条件 |

| `CALIBRATE` 让玩家知道手被识别 | PALM 亮起图标，实时状态文字 | 动态手掌轮廓、区域与置信度提示（仅有实际字段才使用） | 一次稳定 PALM，或玩家选择辅助继续 |

| `SEA` 小橙鱼与挥手→鱼避开→静止试探回归→初次“请勿喧哗”→再操作验证 | 至少一个独立运动的小橙鱼＋两组占位鱼；`WAVE/MOVING` 强化水流，`STILL` 连续降低水流和增加距离；**再次挥手必能把鱼赶走**；首次聚鱼后不自动转场 | D 分层鱼替换占位；小鱼独立犹豫；暗蓝遮罩随亲近度局部减弱；提示 `S01`、延时 `S02`、首次聚鱼后 `SEA01`，保留可逆操作，`S03` 轻提示 | 至少一次真实有效挥手→静止接近；留足再试验时间，玩家点击柔和“继续”或明确完成条件 |
| `SEA` 可选 P1 捧鱼 | **不阻碍主线，默认跳过** | 在接近阈值后提示双手轻捧；B 如交付稳定 `CUP` 则小鱼**自己游入**，不能做“抓鱼”小游戏；提供辅助点击替代 | CUP 成功或跳过；不改变主线 |
| `RETURN_WARD` 便签改写；妹妹回护士；留两张票、问哥哥是否也想去 | 静态病房图＋字幕 `R01,W04,R02,R03,R04,R05`、划掉 W04 的 CSS 演出 | 看不见护士实际全文的主观碎字幕；妹妹先回头、主动推票；R05 PALM 回应可选，未识别可以辅助继续 | 字幕读完与角色主动动作完成，不强制识别才能见到镜子 |

| `FINAL_DOOR` 旧动作有反馈却不强制推进→妹妹先放下手→有效静止→她先伸手→玻璃消失→完整对话→最终 PALM | 病房图加可渐隐玻璃层；`F00,F0A,F01,F10,F02,F12` 按**演出时机**播放。静止连续累计约 2 秒后先播放妹妹主动伸手的图标/特写占位，再消玻璃、揭露文本；最后 PALM 触发结局 | D 替换局部伸手图；提示只熄灭**剧情命令**，暂停/帮助/退出常在；音乐先收掉，伸手后慢慢恢复；可选 F0B、F11；哥哥完整第四音仅在最后 PALM 之后出现 | 妹妹先主动后，玩家最后 PALM（有辅助继续） |
| `AQUARIUM` 明亮水族馆，两人平等地看鱼 | 直接复用深海图片、取消暗遮罩，`END00` | 等量构图：两人并肩可用简单剪影；鱼自由游动；妹妹完整主题、哥哥终于完整主题 | 字幕读完 |
| `END` 结束文字与重玩退出 | `END01,END02` 及重玩/退出按钮 | 连同隐私提示和设置入口；重玩应重置全部状态 | 用户主动选择 |

**剧情事实边界**：妹妹听力恢复不是“突然奇迹”；沟通时的文本为“动作释义／可靠沟通屏”，不能让哥哥的主观误解变成系统的客观事实。病房的 `GOOD` 是哥哥真诚的鼓励，但其自我价值被“照顾者身份”绑住；妹妹的主动性必须在开头、返回病房和终局重复出现。全游戏的动作图示属于游戏自定义动作，不声称是真实完整手语；真实听觉障碍不能被处理为恐怖效果。

## 3. 场景之间的转场方案：全都先有廉价版，之后局部升级

| 转场 | 第 0/1 阶段 | 后期精修路径（不要求 D 重画） | 触发防护 |
|---|---|---|---|
| 病房 → 深海 | 双图交叉淡入淡出 0.8–1.2s，音乐淡出淡入 | 镜头偏移到病房左侧窗户；窗内提前出现海面波纹，`clip-path` 遮罩从窗户向全屏扩张，原 BGM 第四音缺席 | 只能由 W03 完成触发一次 |
| 深海 → 返回病房 | 水纹收束、交叉渐变，复用同一病房图 | 小鱼的暖光与窗户、门票亮部匹配剪辑 | 首次聚鱼后必须让玩家有时间再次实验，不直接转 |
| 返回病房 → 镜子 | 病房变暗，覆盖简单镜框 | 复用窗玻璃倒影、CSS 模糊／半透明人物剪影 | 回病房 R05 后，未面捕仍可推进 |
| 镜子 → 最终玻璃 | 镜框渐变成半透明玻璃层 | 镜面反射变成妹妹身前的玻璃；旧手势只有细小光圈反馈 | 只在正式进入 final_wait 后累计静止 |
| 最终玻璃 → 水族馆 | 先伸手、玻璃淡出、亮海交叉渐变 | 玻璃退去后匹配小鱼与妹妹主动接近的视觉运动 | 不可音乐先高潮、玻璃先消再伸手 |

所有转场由 `TransitionManager.transition(from,to, effect)` 返回 Promise，**正在转场时拒绝重复触发**；首轮只用 CSS opacity，精修时替换 transition 插件，剧情状态不变。全屏素材维持 16:9 的统一 `sceneStage`，不同分辨率用 letterbox，窗口坐标按显示容器百分比配置，避免转场强绑 1920×1080 像素。

## 4. 玩法状态与可测试规则

- 统一游戏状态：`sceneId`、`stepId`、`modalOpen`、`inputMode`、`transitioning`、`seenLineIds`、`seaHasWaved`、`seaGatheredOnce`、`seaExperimentedAgain`、`finalWaitStart`。
- 统一表现状态：`palmX/palmY`（有数据才更新）、`waterIntensity`（0~1）、`fishProximity`（0~1）、`specialFishProximity`（0~1）、`glassOpacity`（0~1）、`captionId`、`audioCue`。
- 深海进入时先等玩家至少一次挥手，不能因进场时天然不动而“自动解谜”；`WAVE` 产生短促明显逃离，实时 `MOVING/motion` 持续决定水流；有效 `STILL` 使水流逐渐减弱、约 0.5 秒可见试探靠近、约 2 秒形成聚集；从任意接近度重新大幅移动，鱼能再逃。**首次成功聚鱼后既不锁定鱼，也不马上跳场景**。如果仅有 WAVE 脉冲，连续鱼的行为可以依照连续 SILENCE_STATE 做基本插值。
- 不能让系统每次收到重复 PALM 就推进多个步骤；只在要求 PALM 的步骤消耗一次、加至少约 0.4s 重新武装限制。GOOD 是可选的鼓励，不必让妹妹继续强调“需要哥哥”。
- `SILENCE_REACHED` 可以记录辅助日志，但**深海**依赖 `SILENCE_STATE` 连续帧，**终局**在 `F0A` 之后由本场景新鲜、有效的 STILL 帧重新累计约 2 秒；`NO_HAND`、服务失联、菜单打开都清零。出现 CUP 时先看 `seaHasGathered` 和 P1 功能开关，才允许小鱼主动触碰。
- 加 `debug`: 键盘 `P`=PALM、`G`=GOOD、`W`=WAVE、`M`=MOVING、`S`=保持/切换 STILL、`N`=NO_HAND、`C`=模拟 CUP；界面顶端必须常显“模拟输入”，正式录屏不可假扮为摄像头演示。

## 5. 从现在开始的分阶段时间表

### 第 0 阶段（**接下来约 2 小时**）：先拿到可运行骨架

| 时间 | 只做什么 | 退出标准／超时降级 |
|---|---|---|
| 0–15 分 | 整个 Qt 工程另存，只读保存；新建独立 `web_pivot`；浏览器能通过 Python 本地服务器显示原病房/深海图 | 若 15 分做不到，停止迁移，排查本地服务/素材路径 |
| 15–40 分 | 全九场景可进入的**占位路由**、原 `story.json` ID 读取、可跳场景的调试栏；菜单、字幕基础组件 | 无正式图用渐变占位，先不写高级转场 |
| 40–75 分 | 深海手势模拟输入接鱼群连续属性；WAVE→逃→STILL→回→再次 WAVE；独立小鱼至少一个 | 如果还在 PPT 式整图切换，优先修深海，不去做 CUP |
| 75–100 分 | 病房 PALM/可选 GOOD + 终局 F0A→场景本地 2 秒 STILL→妹妹先伸手→PALM；三段串成小闭环 | 其它场景仅按剧本显示字幕，可以占位，**不虚报全程完成** |
| 100–120 分 | 若 B 的程序可独立运行，再桥接真实事件；通关至少一次；录 60–90 秒备用演示；提交稳定版 | B 桥接失败则保留标识明显的模拟原型，明天继续；不要在最后 20 分钟增加新功能 |

**两小时后现实可交付**：一个有九个场景槽位、原剧情 ID、可展示真实设计闭环（可能仍为模拟输入）的网页框架；不是经新玩家验证的情况 C 完整作品。

### 第 1 阶段（其后约 2–4 小时）：真实输入 + 深海核心完成

A 对接 Python worker 真输出；B 验证自己原脚本不依赖旧 Qt、确认命令和工作目录、修复 WAVE/STILL 误判；D 交已有分层鱼素材。做三次真实挥手/静止往返；模拟模式与真实模式隔离；`NO_HAND` / 断流不触发静止。保留可关闭提示的 T8 盲测入口。**阶段门槛：真实摄像头反复驱动真实鱼，而不只是预制动画。**

### 第 2 阶段（约 3–5 小时）：九个场景全部能走到，先剧情再演出

A 实现全 `sceneOrder` 和可跳过镜子；C 提供冻结 `story.json` 和 **额外一条**可选 GOOD 台词/捧鱼提示，A 不覆盖源文件、先映射既有 ID；D 原有两张背景足够，其它用复用背景、镜框遮罩和字幕补位。**阶段门槛：无开发者手动跳场景，从 CONSENT 到 END 自动/互动按条件全通；无摄影头也可经辅助方式通关。**

### 第 3 阶段（约 2–4 小时）：把“完成了功能”升级为“会讲故事”

依次精修：病房妹妹先手势图、窗户转海、深海粒子和小鱼犹豫、返回病房便签删除动效、镜子停顿、终局**妹妹先伸手**与玻璃消失先后、明亮水族馆。加入四音主题：妹妹完整（Do–Mi–Sol–高Do）、哥哥前期末音空拍、最后 PALM 才第一次补完末音；调高末音持续时间确保非音乐专业玩家也能觉察。辅助信息均有字幕与可见反馈。**阶段门槛：即使静音，玩家也看懂妹妹主动性；开声音可觉察前后旋律变化。**

### 第 4 阶段（仅前 3 阶段稳定后）：P1 双手轻捧小鱼

B 若真正确认能稳定输出 `CUP`（双手在场、捧物姿势保持等具体条件及冲突由 B 实测），A 仅新增深海分支，D 只提供手势示意／一条独立鱼，C 对接原 `S04` 的 P1 文案或增量；鱼主动游入，失败可跳过，不能逼玩家抓住鱼。**阶段门槛：CUP 不与 PALM/WAVE/STILL 冲突，失败不阻碍主线。**

### 第 5 阶段（比赛前）：情况 C 必需的可靠性与真实试玩

## 8. 交给开发 AI 的工作方式：一次只执行一个可运行阶段

不要把全部文件一口气重写。按如下循环：

1. **先审计**：展示当前目录树、真实 B 输出格式、当前可运行命令；说明哪些未证实。
2. **只实现当前阶段**：给出改动文件清单；禁止改原 `story.json` 和 `vision` 识别算法；现有工作先备份。
3. **自己运行**：验证页面打开、运行控制台、模拟输入重放并检查关键状态；未测试不得声称完成。
4. **提交稳定版本**：提供启动命令、验收步骤、失败回滚命令和下一阶段的固定输入输出契约。

第一条命令应当能用**零新增 npm 依赖**启动最小网页；替换美术/BGM/剧情，不应改变引擎。不能因渲染精细打磨让核心交互重新变成 PPT 图片切换。
