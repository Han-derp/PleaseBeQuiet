# 《请勿喧哗》五人黑客松开发方案

**版本**：机制反转＋双层静止信号 / 五人 48 小时 / HLD → LLD → 排期 → 验收 → 路演  
**T0 已冻结**：静止双层契约；菜单 > 剧情手势 > 静止；终局回应而非开门；T8 仅验证 30 秒闭环。  
**设计基准**：沿用原《请勿喧哗》v3 的“床旁沟通屏始终清晰、环境声音字幕碎裂、哥哥与小满的视觉沟通”世界观；将核心反转改为**玩家最后需要停止操作**。比赛主题和时长以现场公告为准。

> **一句话提案**：你以为需要不停做手势，才能让世界听见自己；最后才发现，有时停止动作，回应才会靠近。
>
> **交互公式**：`做手势 → 世界回应`（教会规则）→ `做得越多 → 鱼群越远`（破坏预期）→ `安静 2 秒 → 世界靠近`（玩家主动发现）→ `最终静止 → 镜中人主动伸手，阻隔消失`（关系回应）。

# 一、概要设计 HLD

## 1. 产品目标与不可妥协的体验

一场 **6–8 分钟** 的全程视觉化摄像头交互短篇，供不熟悉手语的玩家独立游玩；配套 **90 秒试玩版** 和约 **3 分钟路演**。主要展示两次交互震撼：

1. **第一个啊哈**：深海中手势越激烈，鱼越疏远；静止下来，它们反而聚拢。这个规律通过画面与操作被玩家发现，而不是先用教程告知。
2. **第二个啊哈（换质而非重复）**：终局玩家再做任何手势都无效；床旁沟通屏熄灭，小满先停下动作。玩家静止后，**不是门打开，而是镜中角色主动伸手、隔在双方之间的玻璃消失**——第一次静止改变鱼群，第二次静止让关系发生回应。

**不是**：真实手语翻译器、精神健康检测工具、要求玩家微笑的情绪考试、宣称模拟所有听障者经历的产品。全部交互手势注明“本作自定义动作，不等于标准手语”。

### MVP 冻结范围

| 必须有 P0 | 可做 P1（仅 P0 稳定后） | 暂缓 P2／明确砍掉 |
|---|---|---|
| 病房 → 深海 → 病房／镜子 → 明亮水族馆（复用深海资产） | 高质量水波转场、鱼群个体细节 | 游乐场、厨房、电话亭、事故公路等独立场景 |
| `PALM`、`GOOD`、`WAVE`；`SILENCE_STATE`（连续状态）＋`SILENCE_REACHED`（一次脉冲） | 第四种手势 `POINT`、双手动作 | 12 种手势、连续手语翻译或训练新模型 |
| 掌心移动＋稳定停留 0.8 秒完成所有选项 | 点头确认作为可选彩蛋 | 精细视线追踪、默认头部＋点头、PyAutoGUI 全局鼠标 |
| 深海中的动静反向鱼群；终局静止后镜中角色主动伸手、玻璃消失 | 鱼群动画与粒子高级效果 | 强制微笑、依据皱眉惩罚或锁死剧情 |
| 镜子内眨眼、抬眉、嘴角变化（全部可跳过） | 按需加载 Face 模型、更多镜像表情 | 全程面部常开、情绪分类、真实人脸强制叠图 |
| 授权、校准、暂停、退出、摄像头丢失恢复、动作辅助 | 设备性能面板 | 无退出按钮、强行关闭游戏、原始视频上传 |

## 2. 叙事基准：真相不等于“她假装失聪”

**正式设定**：小满**曾有听力障碍，并在故事开始前恢复听力**。她仍主动和哥哥使用手语／视觉沟通，是因为哥哥事故后失去听力与发声能力，视觉交流是两人真正可用、平等的沟通方式。哥哥在创伤与自我否定中，误把“妹妹仍在用手语”理解成“妹妹仍然听不见、还需要我治好她”。

- 病房中的小满不会假装看不到声音事件；可以让她在哥哥背对护士时自然回应一次，作为可回看的伏笔。
- 揭示不是“小满欺骗了你”，而是“小满的手势一直是在向你说话”；她也可以承认自己不知道怎么开口说明恢复事实。
- 不使用“你才是真正的聋哑人”来训斥玩家，不把听力或发声障碍当成恐怖身份；“听”在游戏标题中的隐喻指接纳与留出交流空间。
- 玩家不需理解或接受特定心理诊断才能通关；哥的内心是叙事角色的处境，不是通过玩家表情得出的临床结论。

**主揭示字幕（建议）**：

> 小满：「我的听力早就恢复了。可是我们的手语从来不是假装。」  
> 小满：「我一直在和你说话，也一直在等你愿意停下来，看看我。」  
> 镜面文字：「不用每一秒都证明自己有用。请勿喧哗。」

## 3. 四段玩家旅程与情绪曲线

| 时段 | 空间 | 观众看到的动作 | 隐藏机制与意义 | 通关 |
|---|---|---|---|---|
| 0:00–1:30 | 病房／沟通屏 | 按提示 `PALM`、`GOOD`，掌心停留选选项 | 建立“持续做动作才能交流”的操作习惯；背景出现“恢复”碎片 | 完成两次回应 |
| 1:30–3:30 | 深海 | `WAVE` 转场，`PALM` 让少量鱼靠近，随后快速挥手会让鱼散开 | **反向反馈**：高速运动疏散鱼；静止时鱼回来，最好让玩家自己发现 | 首次触发静止反馈，童年玩具浮现 |
| 3:30–5:30 | 返回病房／镜子 | 观察小满与护士互动；镜中人物模仿玩家眨眼／抬眉（可跳过） | 揭示妹妹的恢复与视觉沟通缘由；停止动作再次被赋予意义 | 字幕揭示完整，无面部检测也可继续 |
| 5:30–6:30 | 最终“隔阂之镜”→明亮水族馆 | 常规手势均被识别却不再产生效果；沟通屏熄灭，小满先停下；玩家静止 | **意义升级**：玩家不再操纵事物；镜中角色先伸手，玻璃自行消散，形成双向回应 | `SILENCE_REACHED` 2 s 且仅消费一次 |

**防剧透的提示层级**：终局 0–5 s：沟通屏逐渐熄灭、小满放下双手，留白等待；6–12 s：镜框出现微弱光纹暗示“她在等”，无直接解题提示；12 s：独立的系统帮助层（不依赖已熄灭的剧情沟通屏）提示“也许可以先放下双手”；20 s：帮助层显示“保持静止约 2 秒 / 使用辅助完成”。玩家的退出、摄像头故障和辅助入口始终清晰、可访问，不参与熄灭特效。

# 二、详细技术设计 LLD

## 4. 技术选型和分层

**优先栈**：Vite + TypeScript、PixiJS（2D 场景）、MediaPipe Hand Landmarker（常规输入）、MediaPipe Face Landmarker（镜子按需启用）、浏览器本机摄像头、HTML/CSS 沟通屏。使用本地模型与素材，在现场展示电脑的 Chrome/Chromium 浏览器运行，无需服务端，也不以 PyAutoGUI 操作系统鼠标。

```text
摄像头（video only）
  ├─ 手部关键点 ─→ 姿态判断 PALM/GOOD ─→ 轨迹 WAVE ─→ 防抖
  │                                           └─ 静止检测 SILENCE
  └─ 面部关键点（仅 MIRROR 场景需要）─→ BLINK/BROW/MOUTH_MOTION
                                       ↓
                InputBus（统一、去重、场景门控）
                                       ↓
                      StoryFSM（对话及四幕状态机）
                                       ↓
        PixiJS 病房/深海/镜像/水族馆 + DOM 沟通屏
```

**资源与计算管理**：输入 640×480 作为初始候选，手部推理 10–15 Hz 起测，PixiJS 独立渲染；Face 模型只在镜子场景加载／启动，退出即停用。若首次按需加载延时影响演示，可在资源加载页预载 Face 模型但不持续推理。最终以现场电脑实测帧率为准。权限仅申请 video，不申请 audio。

## 5. T0 冻结：事件契约、优先级与消费语义

### 5.1 核心区别：状态可以持续，剧情脉冲只能发一次

- **`SILENCE_STATE`** 是当前输入状态，在游戏更新时持续可读，或按约 **10 Hz** 推送给深海鱼群力场；它**不能直接触发剧情**。`holdMs` 表示符合资格的本次连续静止时长。
- **`SILENCE_REACHED`** 是边沿事件：仅在同一次有效静止 **首次跨过 2000 ms** 时生成一次候选；终局接受它后用 `finalConsumed = true` 锁定节点。继续静止不会重复触发。离开静止后才能重新武装检测器；切换场景须重置累计时长和边沿标记。
- **`ACCESSIBLE_SILENCE`** 是 **C 的辅助 UI 发给 A 的 `SYSTEM` 请求**，绝不能由 B 的摄像头识别伪造。A 校验当前确实处于终局，并在辅助菜单关闭、0.3 秒屏蔽期结束后，合成带 `source: 'SYSTEM'` 的终局通关事件。

```ts
// T0 冻结的公共消息；其他模块只订阅，不自行扩展字符串。
type Scene = 'CONSENT' | 'CALIBRATE' | 'WARD' | 'SEA'
  | 'RETURN_WARD' | 'MIRROR' | 'FINAL_DOOR' | 'AQUARIUM' | 'END';
type HandAction = 'PALM' | 'GOOD' | 'WAVE' | 'POINT';
type SilenceMode = 'MOVING' | 'STILL' | 'HAND_AWAY' | 'UNAVAILABLE';

type InputMessage =
  | { kind: 'GESTURE'; action: HandAction; confidence: number; at: number }
  | { kind: 'SILENCE_STATE'; mode: SilenceMode; eligible: boolean;
      holdMs: number; motion: number; at: number }
  | { kind: 'SILENCE_REACHED'; mode: 'STILL' | 'HAND_AWAY';
      source: 'VISION'; holdMs: number; at: number }
  | { kind: 'PALM_DWELL'; zone: string; dwellMs: number; at: number }
  | { kind: 'FACE_MOTION'; action: 'BLINK' | 'BROW' | 'MOUTH';
      value: number; at: number }
  | { kind: 'SYSTEM'; action: 'CAMERA_LOST' | 'CAMERA_RESTORED'
      | 'ACCESSIBLE_SILENCE' | 'SKIP' | 'EXIT'; at: number };

type FinalResponse = { kind: 'FINAL_RESPONSE';
  source: 'VISION' | 'SYSTEM'; mode: 'STILL' | 'HAND_AWAY' | 'ACCESSIBLE' };
```

模块边界：**B** 只输出视觉事件（含 `SILENCE_STATE` 和来自真实视觉的 `SILENCE_REACHED`）；**C** 输出菜单停留和辅助请求；**A** 负责优先级、场景门控、终局的 `FINAL_RESPONSE` 合成、一次性消费；**D** 只使用 `SILENCE_STATE` 和剧情事件做动画；**E** 只使用剧情状态编排对白，不直接读关键点。

### 5.2 输入仲裁优先级（写进代码，而不是口头约定）

**菜单 > 剧情手势 > SILENCE**。一个帧周期内先判断菜单（A 在门控开启/关闭时通知 B 重置静止与手势候选）：

1. **菜单打开**：只接受掌心停留、辅助按钮及退出/暂停等系统操作；彻底屏蔽剧情 `GESTURE`、`SILENCE_STATE` 对场景的作用和 `SILENCE_REACHED`，并清空静止累计时间；手部追踪仍可用于绘制菜单指针。
2. **菜单刚关闭**：重置手势轨迹和静止检测历史，**阻断剧情输入 300 ms**。如果选择了“辅助完成”，暂存请求，待屏蔽期结束再由 A 以系统来源执行，不能趁菜单未关闭直接穿过优先级。
3. **正常剧情**：先消费当前场景认可的手势；再把连续 `SILENCE_STATE` 提供给场景物理效果。`SEA` 可用它改变鱼距离，但不得直接引发剧情节点；`FINAL_DOOR` 才允许 A 把一次 `SILENCE_REACHED` 映射为 `FINAL_RESPONSE`。剧情手势与静止转场不能在同帧双重消费。
4. **场景切换**：重置 `holdMs`、`reached`、手势候选及上一场景缓冲，避免深海尾声的静止被终局沿用；每个终局节点有独立 `finalConsumed` 锁。

```ts
function routeFrame(input: FrameInput, now: number) {
  if (ui.menuOpen) {
    bInput.resetSilenceAndGestureCandidates(); // A 下发门控；B 保留手部菜单指针
    ui.handleDwellAndSystem(input, now); // 不发布剧情消息
    return;
  }
  if (now < ui.menuClosedAt + 300) {
    bInput.resetSilenceAndGestureCandidates();
    return; // ACCESSIBLE 请求交给屏蔽期后单独处理
  }
  if (pendingAccessibleRequest && story.scene === 'FINAL_DOOR') {
    pendingAccessibleRequest = false;
    story.consumeOnce({ kind: 'FINAL_RESPONSE', source: 'SYSTEM', mode: 'ACCESSIBLE' });
    return;
  }
  const gestureConsumed = story.tryConsumeGesture(input.detectedGesture);
  const state = input.silenceState; // B 检测器产生的持续状态
  if (story.scene === 'SEA') sea.onSilenceState(state); // 仅物理反馈
  if (!gestureConsumed && story.scene === 'FINAL_DOOR' &&
      input.silenceReached && !story.finalConsumed) {
    story.consumeOnce({ kind: 'FINAL_RESPONSE', source: 'VISION',
      mode: input.silenceReached.mode });
  }
}
```

上面是**仲裁伪代码**而非可直接运行的逐帧程序；真实实现中应采用单调时钟 `performance.now()`、按时间戳限制更新频率，并在异常帧时暂停计时。B 的边沿事件可先进入队列，再由 A 决定是否放行，不能由 D/E 直接订阅原始剧情脉冲。

## 6. 新增核心：`SILENCE` 静止／离镜头双路径

### 6.1 正确定义“静止”

不要只计算**速度的方差**：手在镜头前匀速移动时，速度方差也可能接近零。应同时测量**手掌中心的平均位移速度**和**位置分散度**，并与当前或校准过的掌宽归一化，以抵御不同镜头距离与轻微自然颤动。

- 观察窗口：最近约 0.8 s、至少 6 帧有效同一只手轨迹。
- `speed = median(distance(p[t], p[t-1]) / palmWidth / dt)`；起始试验阈值需现场校准，例如低于每秒约 0.35 个掌宽（仅供调参起点）。
- `spread = max(distance(p[t], medianPosition)) / palmWidth`；初始试验阈值约 0.2–0.3 个掌宽，按设备和玩家调整。
- 当两只手可见时**都**需要满足静止；若至少一只手移动，则不触发。双手先后进出取景框时重置计时，避免误跳。
- 持续达到 **2.0 s** 前，每约 100 ms 发布/更新 `SILENCE_STATE`；第一次跨过 **2.0 s** 才产出一个 `SILENCE_REACHED { mode: 'STILL', source: 'VISION' }` 候选，继续保持不再发。识别短暂闪断（例如少于 0.25 s）可以暂停而非增长计时；超时丢失则依据视频健康状况重置或重新判定 `HAND_AWAY`。

### 6.2 “手离开镜头”不是“摄像头故障”

把无手部关键点直接等同静默会把黑屏、断流、模型尚未加载或遮挡误判成通关。`HAND_AWAY` 必须同时满足：

1. `video.readyState`、连续视频帧、模型运行状态正常；镜头权限未被撤销；
2. 近期校准及玩法期间**曾稳定检测到该玩家的手**；
3. 两只手均连续未检出约 2.0 s；
4. 当前是 `SEA` 或 `FINAL_DOOR` 场景，且无菜单挡住识别区。

极暗画面、视频冻结或摄像头断开不计时并显示完整错误提示。**单靠连续视频帧并不能准确区分“人将双手移出画面”和“镜头被物体遮挡”**；亮度/纹理阈值只能降低风险。T8 原型只验收 `STILL`，`HAND_AWAY` 是 P1 备选路径：只有现场实测足够可靠才开启，否则关闭，保留 `STILL` 和辅助路径。

### 6.3 可及性与意外感并存

`SILENCE` 是一种**游戏输入**，不是对用户身体状态或人格的评价。将三条路线同时做进主线：

1. 自然发现：停止挥手、让手静止 2 s；
2. 另一种自然发现：把手退出取景框约 2 s（仅在视频健康前提下）；
3. 无法长期静止或摄像头不稳定时：系统帮助层始终可以打开。辅助界面中的“完成静止”按钮掌心停留 **0.8 s**，由 C 提交 `SYSTEM.ACCESSIBLE_SILENCE`；A 在菜单关闭并经过 **300 ms** 缓冲后，合成 `FINAL_RESPONSE { source: 'SYSTEM', mode: 'ACCESSIBLE' }`。也提供键鼠/触摸保底，且如实说明这是辅助路线。

辅助选项需要清晰存在，但不在第一次深海反转前突出提示；不能把不能静止的玩家排除在结局之外。

### 6.4 静止检测器输出示例（边沿触发与复位）

```ts
class SilenceTracker {
  private holdMs = 0;
  private reached = false;
  private lastMode: 'STILL' | 'HAND_AWAY' | null = null;

  reset() { this.holdMs = 0; this.reached = false; this.lastMode = null; }

  // 仅处理已经过健康检查、去抖/时间滞回和两手约束的分类结果。
  update(mode: SilenceMode, eligible: boolean, elapsedValidMs: number, now: number) {
    if (!eligible || (mode !== 'STILL' && mode !== 'HAND_AWAY')) {
      this.reset();
      return { state: { kind: 'SILENCE_STATE', mode, eligible,
        holdMs: 0, motion: 1, at: now }, reached: null };
    }
    if (mode !== this.lastMode) { this.reset(); this.lastMode = mode; }
    this.holdMs += elapsedValidMs;
    const state = { kind: 'SILENCE_STATE' as const, mode,
      eligible: true, holdMs: this.holdMs, motion: 0, at: now };
    if (this.holdMs >= 2000 && !this.reached) {
      this.reached = true;
      return { state, reached: { kind: 'SILENCE_REACHED' as const,
        mode, source: 'VISION' as const, holdMs: this.holdMs, at: now } };
    }
    return { state, reached: null };
  }
}
```

**必要的单元测试**：静止持续 2.5 秒只发一次；持续 4 秒不重复发；中途移动后重新累计；菜单开启期间不累计；菜单关闭的 300 ms 不累计；切场景不继承；一手动一手静不触发；视频停帧不计时；辅助按钮只能产生 `SYSTEM` 来源的结果。

## 7. 深海逆向规则与 T8 唯一关卡

### 7.1 制作规则

**起手（约 5–10 秒）**：屏幕给出一个最简单的挥手示意。玩家挥手时必须立即看到水流跟手运动，以证明识别确实成功；与此同时，鱼群明显朝边缘退开。强化“挥手被识别了，但我反而赶走了鱼”的冲突，不添加解题文字。

**玩家发现（约 10–25 秒）**：挥手幅度或速度越大，鱼群退得越远。手势逐渐减小时鱼游动减缓；`SILENCE_STATE` 表示有效静止约 1 s 时，先让一条鱼明显转身探近；约 **2 s** 时鱼群全部靠近。**深海的移动只订阅状态**，不能通过 `SILENCE_REACHED` 反复触发故事。

**完成条件**：`SEA` 根据鱼群距离达到近点以及 `SILENCE_STATE.holdMs >= 2000` 的画面结果，触发自身的一次 `FISH_RETURNED` 场景结果；T8 原型用同一条件出现标题字幕“请勿喧哗”。这与终局消费的 `SILENCE_REACHED` 严格分离。

**降级提示（完整游戏启用，不用于首次盲测）**：8 秒无进展时，让一条远处的鱼自行试探靠近；18 秒后出现“试着停一会儿”。测试前不要向玩家解释答案。

### 7.2 T8 的范围严格锁死为 30 秒

```text
挥手成功 → 水流同步、鱼明显远离
        → 玩家自发停止动作并持续约 2 秒
        → 鱼群主动靠近
        → 屏幕只出现「请勿喧哗」
```

**T8 不做完整病房、不做面部、不做剧情镜子、不做复杂转场**。B 用真实摄像头输出状态，D 把鱼群距离变化放大到远处也看得懂，A 连通状态与 PixiJS，C 先交付最低可用的菜单/重置，E 主持外部观察。

**盲测方法（3 名此前未参与设计的人，每人最多 30 秒）**：只说“试试看让鱼群靠近”，不展示“停下来”的文字，不用语气、目光或动作暗示。记录每个人是第几秒第一次主动停下、是否在无提示下看到鱼靠近、是否复现成功。结束后只问：“你什么时候发现要停下来？”目标是**至少 2/3 自发发现并复现**。3 人样本只是 T8 设计决策信号，不是证明项目一定成功的统计结论。

**失败时修改顺序**：首先增加挥手后的鱼群退距与方向感，其次加入低速时单条鱼的试探，再调整环境引导；不要先补说明文字，更不要靠主持人口播暗示答案。改动后换新的未接触玩家复测，避免熟悉规则带来的假阳性。

## 8. 面部只用于镜像同步

- 面部追踪非主线通关条件；可以在配置中完全关闭，剧情仍完整。
- `FACE_MOTION` 仅驱动镜中**抽象角色**的眨眼、抬眉、嘴角形变，目标是展示细微同步带来的“被看见感”。不要弹出快乐、愤怒或抑郁标签，也不要因表情让小满后退或心电图变平。
- 镜子文案显式告知：**“仅检测面部动作，不判断情绪；可跳过。”** 体验者可同意开启或选择观看默认动画。脸部原始画面默认不保存、不上传、不在结局强制投屏。
- 镜子即使完全无法识别脸，也能在 5–8 秒的对白和动画后正常进入 `FINAL_DOOR`。

## 9. 无键鼠选择固定为“掌心区域停留”

**T0 冻结主选项交互，不再浪费开发时间做头部选择：**

- 每个选项采用覆盖面大的交互区域；通过单掌掌心坐标映射到 UI 屏幕。
- 掌心进入区域后显示 0.8 s 进度环，停留完成才发 `PALM_DWELL`；移出后适度清空进度以防误触。
- 镜头突然丢失时不计时，刚完成选项后设置 0.5–0.8 s 冷却；单帧噪点不能误选。
- 点头确认仅做 P1 彩蛋，不是任何环节的依赖。无摄像头时提供同内容的鼠标／触摸辅助入口。
- **冲突隔离**：菜单开启时屏蔽剧情 `GESTURE`、剧情使用的 `SILENCE_STATE` 与全部 `SILENCE_REACHED`；菜单关闭后先清空缓存并阻断 **300 ms**。辅助请求必须来自 `SYSTEM`，待菜单关闭后才执行。

| 用例 | 期望行为 | 不满足时降级 |

## 14. 三分钟口播与演示（2 分钟体验 + 1 分钟技术）

| 时间 | 屏幕／演示者动作 | 一句话讲述 |

| **1:20–2:00** | 小满回应护士；终局沟通屏熄灭、小满停手；玩家静止后**镜中她先伸手、玻璃消失** | “上一次停止，让鱼靠近；这一次停止，让对方先回应。” |

| **2:40–3:00** | 明亮水族馆、字幕、90 秒试玩入口 | “《请勿喧哗》——有时，停下来才是回应。” |

技术透视**默认常驻展台第二屏**；主路演只在最后约 20–40 秒快速展示必要证据，避免在揭示中途切断氛围。若现场技术故障，使用**明确标注为预录**的备用视频，不将预录伪装成实时。

## 15. 展台试玩与信息伦理

- 展台版 90 秒：病房示意 20 s → 挥手驱鱼 20 s → 静止发现 20 s → 标题与试玩入口 30 s；正式完整版有第二次**关系回应**，不在展台短版提前全部剧透。

# 五、配套「一页纸任务墙」使用方法

仓库根目录同时保存独立文件 **`请勿喧哗_团队一页纸任务墙.md`**，固定贴在团队群公告或白板上。每次站会只更新：今日目标、阻塞、下次交付、责任人、砍掉清单。本文是设计与评审依据，不需要全员每 4 小时重读。

## T0 当场拍板的六件事

1. 确定比赛真实工期、实际路演时间、摄像头授权环境及备用展示电脑。
2. 确定故事正史：**小满曾失聪、故事开始前已恢复；哥哥事故后失听失声；手语是真实沟通不是骗局**。
3. A 在第一小时冻结：`SILENCE_STATE` 连续、`SILENCE_REACHED` 一次，`SYSTEM.ACCESSIBLE_SILENCE` 只由 C 发起；优先级 **菜单 > 剧情手势 > 静止**。
4. T0 固定掌心停留作为唯一正式菜单交互；面部只作用于镜子，绝不阻断主线。
5. T8 唯一验收：**30 秒，挥手→鱼远离→停 2 秒→鱼靠近→字幕“请勿喧哗”**。3 名陌生人无提示测试，目标至少 2 人自发发现；不通过先改鱼距离反馈。
6. 终局不重复“静止→门开”：先熄灭沟通屏、小满先停手，再由镜中角色主动伸手、玻璃消失；独立系统帮助、摄像头故障提示与退出始终可用。
